# System Prompt 改动日志

调优原则（详见 `docs/methodology.md`）：

1. 固定基线：冻结评测集版本 + 温度 0 + 同一模型，先拿到 v1 的分数；
2. 失败聚类：把未通过的用例按原因归类，只针对最大的一类缺陷改；
3. **一次只改一个变量**，否则说不清是哪条改动起了作用；
4. 每次改动都在同一份评测集上全量重跑，记录四维分数、通过率与成本；
5. **无效改动也要记**——这一条最能证明调优不是碰运气。
